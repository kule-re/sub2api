# WorkBuddy 接入预览版

用户入口：`/workbuddy`（登录后访问），密钥管理页也有入口。

首版支持 Windows x64、国内版 WorkBuddy **5.6.2**、本站 OpenAI 分组的个人 API 密钥。管理员需配置 **HTTPS API Base URL**，网站本身也需通过 HTTPS 访问。URL 可为站点根地址、以 `/v1` 结尾的地址或完整 `/v1/chat/completions` 地址。不支持用明文 HTTP 传递配对码或密钥。

## 发布

本地构建助手：在仓库根目录运行 `powershell -File tools/workbuddy-setup/build.ps1`。需要 Go 1.23 或以上，产物为 `frontend/public/downloads/sub2api-workbuddy-setup-windows-amd64.exe`（Git 忽略二进制）。然后按项目流程构建前后端。

根目录 Dockerfile 会先测试、交叉编译助手，再打包到前端静态文件中。仅替换首页 HTML 无法安装此功能；需要包含新增后端路由和前端页面的应用镜像。其他构建流水线需在前端打包前生成相同文件，缺失时页面禁用配对并说明原因。Windows 发布签名尚未配置，正式公开下载前应为助手签名并发布 SHA256。无需关闭系统安全设置。

原生首页和密钥管理页提供 `/workbuddy` 入口。自定义 HTML 首页按钮也可使用 `<a href="/workbuddy">配置 WorkBuddy</a>`；HTML 仅负责导航，交互在原生页面完成。

## 用户流程

1. 点击官网链接安装 WorkBuddy；已有用户直接配置。助手不会自动接受许可、代替官方登录或静默安装腾讯软件。
2. 建议创建单独的 WorkBuddy 密钥，绑定 OpenAI 分组并设置额度。在页面选择密钥，填写实际可调用的模型 ID。当前没有预置“已验证模型”列表。
3. 下载助手，退出 WorkBuddy（包含托盘）。在网页生成配对码，运行助手选择 `setup`，输入本站 HTTPS 地址和配对码。
4. 核对模型和 API 地址后输入 `yes`。助手发起一次小型 SSE + 强制工具调用测试，可能产生计费；失败不会写配置。测试不执行模型返回的工具。
5. 测试成功后备份配置、追加模型，再提示打开 WorkBuddy；用户自行选择新模型。实际 WorkBuddy 多轮任务尚需验收，单次探测不等于完整兼容。

助手用完退出，不需要 CC Switch。它只检测常见安装路径，也允许用户输入自定义安装位置；会校验 ASAR 中的版本，未知版本、其他发行版、自定义配置目录、目录重定向或同名模型冲突时停止，提示手工配置。不会覆盖其他站点的同名模型。

## 数据与恢复

- `POST /api/v1/workbuddy/pair`：现有 JWT 鉴权，传 `key_id` 和 `model`。服务端校验密钥归属、有效期、配额、分组状态。API 地址来自管理员设置，不接受客户端任意指定。
- `POST /api/v1/workbuddy/redeem`：请求体传 `code`；256 位随机配对码，5 分钟有效。Redis 仅存码的 SHA256 索引及用户/密钥/分组 ID、模型和地址，不存 API 密钥。`GETDEL` 原子兑换（要求 Redis 6.2+）。兑换会再次校验密钥与用户状态；即使后续校验失败，码也失效。
- 两个接口均限流，Redis 故障拒绝请求。敏感响应 `Cache-Control: no-store`，码不进查询串，助手不跟随 HTTP 重定向。反向代理、APM 和外部日志系统也不应记录这些路由的请求/响应正文。
- 配对码具备兑换密钥的权限，不要转发。重新生成不会撤销旧码，旧码最多再存活 5 分钟；撤销密钥会使所有相关兑换失败。配对码只放页面内存，不写 localStorage。
- 助手配置路径为 `%USERPROFILE%\.workbuddy\models.json`。本机 5.6.2 安装包只读核对确认支持顶层数组和 `{ "models": [...] }`，配置合并保留未知字段和已有加密凭据，不解密其他密钥。新密钥按客户端兼容格式写入，文件与备份继承仅当前 Windows 用户和 SYSTEM 可访问的目录 ACL。
- 备份在同目录 `sub2api-setup`，含敏感配置；不自动上传。重新运行助手选择 `restore` 恢复最近一次写入前的原始字节。若配置被 WorkBuddy 或用户继续修改，恢复会拒绝覆盖，需人工比较备份；新建配置的恢复会删除本次新建文件。
- 写入前再次读取并比较文件；助手之间通过锁文件互斥。需要关闭 WorkBuddy，助手不强杀进程。异常退出后可能留下 `setup.lock`，确认没有配置助手运行后才可删除它。
